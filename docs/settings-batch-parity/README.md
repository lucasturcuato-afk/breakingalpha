# Settings batch parity plates

Ten plates, five screens by two themes, design on the left and build on the
right at 390px each. Generated by `scripts/parity-plates.mjs`.

## These are DEV captures, and they have to be

The built half is sourced from `/preview/settings-batch?screen=...&state=...`.
`src/proxy.ts:109-112` opens `/preview/` only when `NODE_ENV` is `development`
or `VERCEL_ENV` is `preview`, so on a production build that route answers 307 to
`/auth`. The plates therefore cannot be captured against `npm run build && next
start`, and were taken against `npm run dev`.

Two things follow, and neither is a defect in the plates:

- **The dark circle at the bottom of the built half is the Next.js dev-tools
  indicator**, not app chrome. It does not ship. It was once reported as a
  production defect covering the tab bar's Today pole, which it is not.
- Anything else dev-only, such as hydration timing, is likewise not evidence
  about production. Every production claim in the PR body is measured against
  `next start` instead, and says so.

## No account appears in them

The built half renders the preview harness, whose fixtures are declared in
`src/components/mobile/preview-settings-batch.tsx` and labelled as fixtures in
the route comment. No signed-in view, no live payload, no per-account figure.
That is deliberate: this repository is public.

## Regenerating

```
npm run dev -- --port <port>
node scripts/parity-plates.mjs http://localhost:<port>
```

The harness renders the prototype at 430 and clips 20px from each edge, so the
design side measures a 390px screen with the prototype's own 350px content
column. `scripts/parity-plates.mjs` explains why in its header.
