# /compose, wired: what these four plates are evidence of

Captured with `node scripts/plate.mjs`, which is the only sanctioned way to
write an image into `docs/` in this repository. All four cleared its guard.

**These are CROPS, not full-page captures.** Each was taken with
`--selector '[data-parity="compose"]'`, so `--full-page` was never passed and
plate.mjs's `--justify` requirement never applied. The crop happens to contain
the whole screen because `[data-parity="compose"]` IS the whole screen: it is
the element under test, not the page. Everything outside it (the app shell, the
mobile tab bar, the desktop half of the route) is excluded.

The exact invocation, for all four:

```
node scripts/plate.mjs --url "http://localhost:3270/compose?stage=<STAGE>" \
  --selector '[data-parity="compose"]' \
  --out "docs/compose-write-path/<STAGE>-390-light.png" \
  --width 390 --height 1700 --theme light
```

`--height 1700` is deliberate and is not a design frame. At 844 the element is
taller than the viewport, and an element screenshot photographs a viewport
RECTANGLE: the `position: fixed` tab bar and the dev-overlay indicator both
painted into the crop. 1700 puts the whole element above them. See the two
plate.mjs findings in PR #709.

| Plate | Reached by | What it proves |
|---|---|---|
| `empty-390-light.png` | `/compose` | The production default. Both fields blank, control locked and reading "Write the claim and your reasoning". No "Preview of the screen" marker line: it came off with `WRITE_PATH_WIRED`, which is what that constant's comment promised. |
| `gradeable-390-light.png` | `?stage=gradeable` | READ AS, both chip rows, a live "Track it". The settles line reads a date FORWARD of today, resolved from `sessionIso`. Under the old fixed `COMPOSE_ANCHOR_ISO` it read 2026-08-13, a date in the past, and every write off it would have been stored ungradeable. |
| `save-error-390-light.png` | `?stage=save-error` | The no-retry ruling, drawn. The reader is told the write was not acknowledged and that their words are still here, is given a real 44px link to `/ledger`, and the control is locked at "Not acknowledged" rather than offering a press that would write a second row. |
| `committed-390-light.png` | `?stage=committed` | "On your ledger", fields readonly, nothing further offered. |

## What these plates do NOT prove, and where that proof lives instead

The headline fix in this PR is that the desk's INFERRED window survives to the
row: the author route reasons its way to spans of 1, 3, 5, 10, 14, 45 and 60
days, none of which is one of the four buckets the chip row names, and the
first wiring rounded all of them to one week.

No plate here shows that, and none can. The dev seed carries a seven-day
proposal, which is exactly on a bucket, so these four images are byte-identical
before and after the repair. Reaching an off-bucket span needs a read-back, and
a read-back is a model call.

That proof is a table, not a picture, and it is generated by
`e2e/compose-write-path.spec.ts` under "the desk's window": every span the
author prompt can produce is driven through the screen with the route
intercepted, and the `resolution_window_end` on the wire is compared against
what the desk asked for. The table is printed by the run and is quoted in the
PR body.
